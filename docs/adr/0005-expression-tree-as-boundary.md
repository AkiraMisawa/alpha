# C#とC++の境界は式木のデータにする

取引のフローは取引記述言語で書かれ、実行すると式木を持つ取引オブジェクトになる。C++のコアにはこの式木をデータとして書き出して渡し、コアは決まった種類の部品を1つずつ評価する。取引記述言語のスクリプトも、それを実行する仕組みも変更しない。C++からC#を呼び戻すことはしない。

コアの部品はすべてテープ上の演算として実装するので、式木を評価すれば微分も同時に得られる。将来時点の時価は、線形フローなら解析式で、行使や条件を含む形なら回帰で求める。この振り分けは商品名ではなく式木の形で決める。

## Considered Options

- 商品ごとの評価式をC++に直接書く: 最初は速いが、取引記述言語と二重管理になり、新しい商品のたびにコアの変更が要る。
- C++からC#のペイオフを呼び戻す: 微分できず、呼び出しのコストも大きい。
- 取引記述言語をC++へ変換する新しい言語を作る: 式木がすでにあるので不要。

## Consequences

- コアが対応していない部品を含む取引は計算できない。最初は為替予約、金利スワップ、通貨スワップ、ヨーロピアン・スワップション、バミューダン・スワップションに必要な部品だけを実装する。
